# KinCheckAPI v0.2.2 更新报告

## 版本定位

v0.2.2 把 CADIR 已支持的六种装配关系接入同一条运动学验证链路，并补齐齿轮齿条（`rack_pinion`）的实际运动验证。运行时仍使用 CadIR Artifact 和 `AssemblyModel`，不改变已有 `Scenario`、`MotionResult` 和 `.kincheck` 的基本用法。

## 主要更新

### 1. 六种 CADIR 关系统一保留和校验

`fixed`、`revolute`、`prismatic` 进入运动树，固定关系会合并刚性组。`gear`、`belt`、`rack_pinion` 保留原始 Connector 两端和关系 ID，作为独立方程参与几何求解、内置物理后端 tendon、残差输出和检查。

这里没有把 CADIR 的传动约束强行压成只引用两个 Joint ID 的 `Coupling`。CADIR 的传动端点本来就是 Connector，行星机构还可能有行星架、支撑和嵌套轴承。保留 Connector 能防止丢失支撑坐标；用户直接创建的公共 `Coupling` 仍按 Joint ID 工作，两者最终使用一致的方程残差语义。

### 2. `rack_pinion` 端到端实现

齿轮齿条关系使用以下 SI 方程：

```text
齿条位移 - 节圆半径 * 齿轮转角 = 0
齿条线速度 - 节圆半径 * 齿轮角速度 = 0
```

本版本已接入：

- `kinematics.solve_position()` 单姿态求解；
- `compute_jacobian()` 和 `analyze_mobility()`；
- 内置物理后端 时间域运动和 `MotionResult.constraint_equation_residuals`；
- `ConstraintEquationResidual.equation_type="rack_pinion"`，单位为米；
- 反向 Connector 顺序的符号处理；
- 沿 Connector 局部 z 轴投影齿条位移，因此 X、Y、Z 方向导轨都可表达。

### 3. 统一传动比检查

`checks.check_transmission_ratio()` 新增：

- `angular_to_linear_velocity`：线速度 / 角速度，单位 `m/rad`；
- `angular_to_linear_displacement`：线位移 / 角位移，单位 `m/rad`。

检查仍然只读取 `MotionResult`，不重新运行后端，也不修改轨迹。结果同时给出测量比例、相对误差、方向一致性、有效样本数和时间范围。

### 4. 新增 ex7 业务模型

`examples/ex7` 是一个齿轮齿条升降机构：一个转动齿轮通过 `rack_pinion` 带动一个直线齿条。验证覆盖：

- Artifact 读取、单位转换和关系 ID 保留；
- 1 个有效自由度；
- 输入 0.5 rad 时齿条移动约 0.01 m；
- 1 rad/s 输入对应约 0.02 m/s 输出；
- 正向和反向 Connector 顺序；
- 内置物理后端 方程残差为零；
- 传动比例检查通过。

## 测试

新增 `tests/test_v022_rack_pinion.py` 15 个行为测试，覆盖版本一致性、Artifact、拓扑、自由度、单姿态、局部轴线、反向端点、时间域运动、方程残差和传动比例。

专项回归结果：

```text
v0.2.2 rack_pinion: 15 passed
v0.2.1 geometry/analysis/examples/equation checks: 65 passed
full suite: 589 passed, 5 skipped
```

5 个跳过项只依赖当前环境中未安装的可选 `simplecadapi`；KinCheckAPI 核心、内置物理后端、ex1-ex7 和结果检查测试均通过。

## 明确边界

本版本没有实现 `cylindrical`、`spherical`、`planar`、`free` 四种多自由度关节，也没有实现 BREP 碰撞/最小间隙、动力学、齿面接触、回差或真实接触力。错误关系会在校验或编译阶段报告，不会静默变成普通树边或伪成功结果。
