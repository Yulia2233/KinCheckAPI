# KinCheckAPI v0.1.3 更新报告

## 版本定位

v0.1.3 把“求解运动”和“检查结果”分开。`kincheckapi.kinematics` 负责调用后端并返回 `MotionResult`；新增的 `kincheckapi.checks` 只读取装配体、工况和运动结果，输出结构化检查报告，不会重新求解或修改结果。

## 已完成的修改

### 1. 新增统一检查模块

新增 `CheckReport`、`CheckSpec`、`CheckSuiteReport` 和 `run_checks()`。目前可用的检查包括：

- `check_constraint_residuals()`：检查普通约束和闭环残差；
- `check_joint_limits()`：检查采样关节位置是否越过装配体限位；
- `check_transmission_ratio()`：比较两条显式运动曲线的比例和方向。

传动比检查支持速度或位移测量、不同采样时间轴插值、窗口起点相对位移、中位数比值、最大/P95误差、标准差、方向一致性、有效样本比例和拒绝样本统计。它不读取齿数、不猜测机构名称，也不启动 内置物理后端。

### 2. 收缩运动学公共职责

`solve_motion()` 仍然是运动求解入口，并在启动后端前先执行 `AssemblyModel` 和 `Scenario` 校验。装配引用错误会抛出 `AssemblyValidationError`，工况错误仍抛出 `ScenarioValidationError`。

`kinematics.verify_transmission_ratio()` 暂时保留为弃用兼容入口，只转发到 `checks.check_transmission_ratio()` 并发出 `DeprecationWarning`。理论行星齿数推导函数已从公开命名空间删除，`TransmissionRatioCheck` 也不再从 `kincheckapi` 根命名空间导出。

### 3. 明确未实现能力

真正尚未实现的运动学能力（单姿态位置求解、可达性、奇异点检测、连接点轨迹检查）、位姿/轨迹目标检查、BREP 间隙和干涉检查、动力学及诊断自动修复，都不再静默返回 `None`。调用时会得到稳定的 `BackendCapabilityError`，其中包含错误码、阶段、对象 ID、建议动作和 `missing_capabilities`。

`dynamics` 模块保持空的公共命名空间，避免声明并不存在的动力学结果。

### 4. 示例和回归

- ex1 继续通过 `checks.check_transmission_ratio()` 验证 64:1；
- ex2 继续验证 20:1；
- ex3 四连杆和 ex4 Theo Jansen 多闭环继续走同一套 `solve_motion()`，并检查闭环状态和全组件轨迹；
- 运动求解结果本身不包含 `expected_ratio`、`measured_ratio`、`stage_checks` 等传动比专用字段。

## 版本边界

本版本不声称完成任意闭环的通用时变位置求解，不声称完成 CAD BREP 碰撞/间隙计算，也不声称完成动力学。错误装配或不支持能力会在 API 层明确报错，不能被当作“检查通过”。

## 验证

v0.1.3 新增检查、能力边界、示例回归和诊断测试；发布前使用完整 `pytest` 套件验证 ex1-ex4 以及公共命名空间。
