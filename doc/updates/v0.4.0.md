# v0.4.0 更新记录

> 历史版本记录：本文准确保留 v0.4.0 发布时的双路径兼容说明。v0.4.1 已将旧
> Artifact 输入路径删除；当前行为以 `doc/updates/v0.4.1.md` 为准。

## 版本目标

v0.4.0 只替换 CADIR 到 KinCheckAPI 的转换层。CADIR dev 现在可以直接产出 MJCF、mapping JSON 和 mesh 目录，KinCheckAPI 新增转换入口，把这些产物转换成现有的 AssemblyModel。

本版本保留原有公共仿真链：

~~~text
AssemblyModel -> Scenario -> solve_motion()
~~~

Scenario、solve_motion()、内置物理后端 backend、MotionResult、clearance、motion envelope、kinematics checks 和业务脚本都没有改变。

## 新增能力

### CADIR MJCF 转换入口

新增：

~~~python
from kincheckapi import cadir

converted = cadir.convert_mjcf(
    xml_path="out/four_bar_linkage/four_bar_linkage.xml",
    mapping_path="out/four_bar_linkage/four_bar_linkage.mapping.json",
    asset_root="out/four_bar_linkage",
)
assembly = converted.assembly
~~~

转换器完成以下工作：

- 读取并编译 CADIR MJCF；
- 校验 mapping schema、稳定 source ID 和 XML 对象名称；
- 解析 mesh 相对路径并校验 asset root；
- 将 MJCF rigid group 转成 Component/Part；
- 将 tree hinge/slide 转成现有 revolute/prismatic Joint；
- 将 closure site/equality 转成现有 Closure 和闭环 Joint；
- 将两自由度以内的 gear、belt、rack-pinion equality 转成现有 Coupling；
- 对 XML equality 与 mapping closure/equality 做双向一一对应校验；
- 保留 MJCF joint axis，并通过 Connector frame 适配现有 backend 的局部 +Z 轴约定；
- 对 CADIR 已编码在初始姿态中的 coupling phase 做归一化，避免 phase 重复施加；
- 将 public site 转成现有 Connector；
- 对 mapping 中显式提供的 collision exclusions 做规范化和严格校验；未提供时保持空排除集合；
- 为每个 rigid group 生成现有 clearance 契约所需的 STL 资产；
- 拒绝空 mesh group 和缺失 public connector ID；
- 保留 XML、mapping、mesh、source ID 和哈希信息到 AdapterResult.source_map；
- 调用现有 assembly/topology 校验，拒绝不完整或无法表达的模型。

旧的 read_artifact()、validate_artifact()、convert_artifact() 和旧 Artifact fixture 继续保留。

### 结构化转换失败

新增 MJCFAdapterError，转换失败统一使用结构化错误码，例如：

- KINCHECK-MJCF-FILE-MISSING
- KINCHECK-MJCF-XML-INVALID
- KINCHECK-MJCF-MAPPING-INVALID
- KINCHECK-MJCF-NAME-UNRESOLVED
- KINCHECK-MJCF-SEMANTICS-UNSUPPORTED
- KINCHECK-MJCF-TOPOLOGY-INVALID
- KINCHECK-MJCF-ASSET-OUTSIDE-ROOT
- KINCHECK-MJCF-ASSET-MISSING
- KINCHECK-MJCF-ASSET-FORMAT-UNSUPPORTED
- KINCHECK-MJCF-JOINT-AXIS-INVALID
- KINCHECK-MJCF-NONFINITE

不会把裸 IndexError、KeyError、XML parser 异常或路径越界直接交给业务调用方。

## 明确不包含的变更

本版本不会：

- 修改 AssemblyModel 数据结构；
- 增加 simulation_source；
- 让 solve_motion() 直接加载 CADIR 原始 XML；
- 绕过或修改 compile_assembly()；
- 修改 Scenario driver、lock、initial state 或 sample 语义；
- 修改 clearance、envelope、MotionResult 和业务脚本；
- 删除旧 Artifact 转换路径。

当前 backend 仍然按照现有逻辑，根据转换后的 AssemblyModel 构造运行时 内置物理后端 XML。若以后要求 CADIR 原始 MJCF 成为唯一运行时事实源，需要另立 backend external-MJCF 方案。

CADIR 的 OBJ 是点时导出输入；转换器会将每个 rigid group 的完整 mesh 集合规范化为 `.kincheckapi-stl/` 下的 STL，并通过 `Part.asset_paths["stl"]` 接入既有 clearance。原始 OBJ 路径仍保留在 `asset_paths["obj"]`、Part metadata 和 source map 中。
