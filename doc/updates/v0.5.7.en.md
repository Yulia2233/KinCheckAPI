# KinCheckAPI v0.5.7 Update

v0.5.7 adds continuous interference checking across recorded trajectory samples and repairs previously missed joint-area interference in the detailed four-bar example. `check_interference()` and `check_minimum_clearance()` still query discrete states; `check_continuous_interference()` now provides auditable interval evidence for explicit component pairs so contact between two samples is not silently missed. This shipment also includes the previously completed [v0.5.6 numerical inverse kinematics](v0.5.6.en.md); its capabilities and result semantics are described separately.

## Continuous interference and TOI

```python
from kincheckapi import ContinuousInterferenceOptions
from kincheckapi.clearance import check_continuous_interference

report = check_continuous_interference(
    assembly=assembly,
    motion_result=motion,
    component_pairs=(("link", "slider"),),
    asset_root=model_dir,
    options=ContinuousInterferenceOptions(
        time_tolerance_s=1e-5,
        minimum_clearance_m=5e-4,
        max_iterations=64,
        max_subdivisions=4096,
    ),
)
print(report.to_dict())
```

The new contracts are `ContinuousInterferenceOptions`, `ContinuousContactEvent`, and `ContinuousInterferenceReport`. Each explicit pair caches its triangle meshes and FCL objects. Between adjacent pose samples, translation is linear and orientation uses shortest-arc quaternion SLERP. Bounding spheres can first exclude clearly separated intervals. A conservative lower bound combines measured mesh distance with relative linear speed and angular speed multiplied by each mesh bounding radius. If that bound is insufficient, subintervals are visited in time order. Only a certified safe prefix advances the TOI lower bound; a separated midpoint cannot exclude earlier contact. The bracket retains the earliest unresolved time through an observed violation. `earliest_contact_time_s` is an upper bound on first contact, at an observed collision time, and `toi_tolerance_met` records whether the requested time precision was reached.

`ContinuousInterferenceOptions.interpolation` accepts `slerp_pose` or `linear_pose`. The latter requires constant orientation for every checked component and returns structured `validation_failed` evidence when that contract is violated. `time_tolerance_s`, `distance_tolerance_m`, `max_iterations`, `max_subdivisions`, `max_queries`, and `minimum_clearance_m` are retained in every report.

## Results, diagnostics, and five review fixes

- `passed`: every requested interval is covered and has a complete conservative distance lower bound above the declared clearance.
- `failed`: initial overlap, contact, or clearance violation was found. Events retain object IDs, interval, earliest-contact upper bound, nearest points, an FCL normal when available, relative speed, and certainty.
- `indeterminate`: no collision has been confirmed, but the time axis, numerical budget, or geometric evidence cannot prove safety. Confirmed collisions retain `failed` after budget exhaustion, together with incomplete-coverage evidence and normalized options.
- `capability_failed`: FCL, trimesh, or rtree is unavailable; the issue code is `KINCHECK-CLEARANCE-CONTINUOUS-BACKEND-UNSUPPORTED`.
- `validation_failed`: the pair selection, parameters, time window, mesh, or interpolation declaration is invalid.
- `partial`: the input motion did not complete; the reason is retained and no continuous safety proof is produced.

Continuous checking accepts only `completed` or `completed_with_warnings` `MotionResult` values. A `partial` result remains useful for discrete diagnosis but can never produce a continuous pass. Attach the report with `record_verification_reports()` to persist it in `MotionResult.metadata`; exporting a `.kincheck` package preserves the event interval, certainty, options, and status on round-trip.

Contact velocity is world-space `v_B(point_B) - v_A(point_A)`, including each body's `v_origin + omega cross r`. Closing speed and contact angle use that velocity and the reported normal; unavailable normals yield null values. The pre-contact state is the last observed separated sample, not a guarantee of an entirely collision-free prefix.

`minimum_clearance_m` is the minimum observed mesh-query distance, not the global minimum; it is null when bounding spheres certify the entire scope without mesh queries. `clearance_lower_bound_m` is populated only when every interval is certified safe and is null for collisions or incomplete coverage. Local certificates remain in `metadata.certified_intervals`.

`checks.check_continuous_interference()` and `run_checks()` reject unrecognized parameters. For example, a top-level `minimum_clearance_m=0.2` returns `validation_failed` with instructions to place it in `options`, rather than silently applying the default threshold.

All five review findings now have reproducing regressions:

| Previous defect | Corrected behavior and evidence |
| --- | --- |
| TOI bisection skipped earlier contact | Certify the safe prefix in time order. The two-obstacle case returns `[0.2666626, 0.2666702] s`, containing the true first contact. |
| Wrapper discarded the safety threshold | Misplaced thresholds return `validation_failed` and instructions to use `options`. |
| Rotating contacts reported zero speed | Evaluate `v_origin + omega cross r` at the reported contact points; the rotation case gives about `2.51818 m/s`, matching an independent calculation. |
| Query exhaustion discarded confirmed contact | Retain events, objects, times, and normalized options. Confirmed contact remains `failed`, with incomplete coverage recorded separately. |
| Local safe bounds became a false global bound | Collisions or incomplete coverage produce `clearance_lower_bound_m=null`; observed distances and local certificates remain separate. |

## Complete four-bar example and geometry-query optimization

[guided_four_bar_actuator](../../examples/guided_four_bar_actuator/README.md) includes CADIR/SimpleCADAPI modeling, MJCF export, independent verification, and `.kincheck` replay. Its base, three links, four physical pins, and guard total nine physical objects. The original scope checked only two non-adjacent group pairs. Expanding it exposed four initial interference pairs: base/crank, base/rocker, coupler/crank, and coupler/rocker. The modeling source and exported geometry now place crank/rocker centers at Z=5 mm and the coupler at Z=10 mm, with 4 mm link thickness and 1 mm between link faces. Link bores have a 2.30 mm radius around 2.00 mm pins; pin lengths, heads, and seating collars match their host faces. Guard feet sit on the base top at Z=-4 mm. Linkage center distances, drive, and the original 0–2 s operating condition are unchanged.

Verification covers all 36 physical pairs, without excluding whole pairs merely because they share a pivot. Six complete rigid-group mesh pairs cover 28 moving physical pairs with discrete and continuous checks. Eight fixed pairs are covered by independent initial mesh checks plus invariant relative placement throughout motion; authored seating faces may touch but cannot penetrate. All 36 pairs also receive an initial physical-mesh check. Discrete checks at 201 sample times and continuous checks over 200 intervals pass. For the 0.1 mm moving clearance requirement, the global conservative lower bound is about **0.101667 mm** and the minimum observed mesh-query distance is about **0.200000 mm**.

The detector negative control lowers the real coupler by 5 mm at t=1 s, deliberately violating the nominal assembly relationship. Both discrete and continuous checks detect the collision. This control is labeled separately and is not part of the delivered model's nominal motion. The package retains acceptance reports, all pair scopes, continuous options and interval evidence, and the negative control; the saved evidence has been read back and checked. See the [collision review](../../examples/guided_four_bar_actuator/output/collision_review.md), [complete JSON evidence](../../examples/guided_four_bar_actuator/output/collision_verification.json), and [visualization package](../../examples/guided_four_bar_actuator/output/guided_four_bar_actuator.kincheck).

Solid containment queries now process 32 vertices at a time. An outside vertex disproves complete containment of that connected solid and ends its remaining queries; later connected solids are still checked. Confirming containment still requires every vertex to pass. This early exit preserves the original predicate without reducing pair coverage, simplifying meshes, or relaxing tolerances. The current example records 3,412 fine mesh queries and 125 extra subdivisions. Shared discrete/continuous query caches, reusable containment spatial indexes, and parallel pair checks are not implemented; timings from different code/model versions are not a controlled cold-versus-warm cache benchmark.

## Boundaries retained

The existing discrete interference, minimum-clearance, and motion-envelope APIs are unchanged. Continuous checking requires explicit nonempty component pairs, at least two component pose samples per object with a common covered time window, valid watertight STL meshes, and python-fcl, trimesh, and rtree. Support depends on rigid geometry and pose trajectories rather than a particular mechanism or joint type. Joint values alone, without component pose trajectories, are insufficient.

The proof applies to the declared piecewise-rigid interpolation model; it does not prove that the physical mechanism follows that interpolation exactly between samples, and it is not an exact BREP/NURBS swept-volume proof. It does not cover deformable bodies, friction, impact, contact forces, dynamics integration, or undeclared pairs. Contact normals and angles depend on available geometric evidence. Unproved intervals remain `indeterminate`. The four-bar acceptance applies to the delivered geometry and the original 0–2 s operating condition, not a full revolution or other loads.
