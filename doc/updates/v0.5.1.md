# v0.5.1 更新记录：全状态装配体整体性检查

## 版本摘要

v0.5.1 新增 `check_assembly_integrity()`，用于验证装配体在静态初始姿态或完整 MotionResult 采样过程中是否始终保持为一个整体。该能力解决了“没有碰撞但装配体已经断开”的问题，例如两个互不接触且没有任何有效关系的正方形，或打气筒活塞滑出筒口后仍未与筒体发生碰撞。

本版本不把“没有干涉”解释成“装配体完整”，也不把单个 Joint 自动解释成允许无限运动。整体性由每个采样状态的有效连接网络判断，连接来源必须明确：机械关系、容纳/导向关系或满足容差的几何连接。

## 新增 API

```python
from kincheckapi.checks import (
    AssemblyIntegrityReport,
    ContainmentRelation,
    check_assembly_integrity,
)

report = check_assembly_integrity(
    assembly=assembly,
    motion_result=motion,
    geometric_connection_pairs=(("component.a", "component.b"),),
    geometric_connection_tolerance_m=1e-4,
)
report.raise_if_failed()
```

`AssemblyIntegrityReport` 保留连接、断开、脱离、越界、失败关系、失败采样时间、每类容差和每个关系的结构化证据。`ContainmentRelation` 用于活塞-筒体、滑块-导轨、销轴-孔等允许运动但不能脱离的关系。

## 判定语义

`check_assembly_integrity()` 在每个检查状态建立 Component 连接图：

- Mechanical relation：Joint、Constraint、Closure；
- Containment/guide relation：用户显式声明的容纳和导向边界；
- Geometric connection：真实三角网格最近距离在 `geometric_connection_tolerance_m` 内且没有超过穿透容差。

`require_single_network=True` 时所有选定 Component 必须属于同一个连接网络。两个远距离正方形即使没有碰撞事件，也会因连接网络数为 2 而失败。活塞在筒内有间隙时可以通过；滑出筒口时因容纳关系越界而失败。

## 容差

- `geometric_connection_tolerance_m`：几何连接的最大允许间隙；
- `penetration_tolerance_m`：允许的数值级轻微穿透；
- `containment_escape_tolerance_m`：允许的数值级容纳边界越界。

所有容差必须有限、非负、使用米，并写入报告。扩大容差不能修复真实分离、越过行程、脱离导轨或穿过筒口的问题。

## 工作流和兼容性

中英文 Skill 在完整 MotionResult 求解后、干涉检查前执行整体性检查。`sampling_scope="initial"` 只表示静态检查，不能证明运动过程；`sampling_scope="motion_result"` 必须检查每个实际采样。现有 `validate_topology()`、FCL 干涉、最小间隙、运动包络和 `.kincheck` schema 保持不变。

## 测试

新增测试覆盖：远距离无关系 Component、Mechanical Joint、容差内/外间隙、穿透、容纳区间、运动中途脱离、partial 结果、零容差、非法参数和报告序列化。每个新增功能至少安排 5 个测试用例，并在中英文 Skill、API 文档、CLI smoke test 和全量回归通过后发布。
