# v0.6.0 review verification

This follow-up repairs the five reported archive/viewer defects. The reproduction suite initially recorded **18 failures, 2 passes**, including re-signed ZIP members, a 2 kg result paired with a 200 kg model, explicit measured payload round-trips, and three static cases with only one motion sample.

The archive now records the pre-payload properties, payload records, model digest and original static request. Export/read replay the request, compare the complete result, and require passing results to pass wrench balance. Truthful failed and indeterminate cases remain valid experimental records. Integer/float JSON normalization does not change the model binding, and contradictory serialized pass flags are rejected. Older motion-only packages remain readable; unbound development physics members require regeneration as `kincheck.static/1.1`.

Both viewer paths emit `physics_case_count`. The actual shipped JavaScript slider handlers are executed by a Node-based DOM/scene harness: all three cases select their own poses while the motion time remains unchanged. Transmission-ratio display is tested with an explicit unit and with the old-manifest `:1` fallback.

## E01 runtime investigation

Commands were executed with this repository's Python 3.12 addon environment against the rated 76-occurrence package. No geometry, pair selection or acceptance threshold was changed during this follow-up.

- Normal baseline verifier: **98.54 s wall**, 90.69 s user, 3.61 s system; completed and passed.
- Instrumented `cProfile` run: **237.34 s wall**, 228.01 s user, 6.21 s system; completed and passed. Profiling overhead and concurrent development activity make this unsuitable as a before/after performance comparison.
- The profile recorded about 1.136 billion calls. The largest cumulative entries were CADIR canonical JSON serialization (112.38 s), canonical JSON parsing/validation (103.92 s), feature-graph loading (55.25 s), artifact-blob validation (46.29 s), and BREP restoration (40.33 s). These entries overlap and must not be summed.
- The verifier performs repeated package validation across mass measurement, interface lookup and the three geometric poses. A 30-second interruption therefore does not demonstrate a functional failure. Reusing an immutable, content-hash-bound validated package is a possible separate optimization; this patch retains all validation and all 2,850 pairs at each pose.

## Follow-up: bound `static_checks`

`static_checks` now require a model digest and a static-result index. Export rejects reports that cannot be replayed. The supported v0.6.0 checks are `check_static_load_limits` and `check_wrench_balance`; each is recomputed from the bound result and stored parameters/evidence. Unknown or unbound reports are rejected rather than included in `acceptance_passed`. The regenerated rated, empty and overload packages contain 12 bound checks each, with `kincheck.static/1.1`, and all three read back with the model digest intact.

The added review regression suite now passes 29 checks in the focused package/viewer group. Full suite result after this correction: **829 passed, 1 skipped**.

## Final pass-flag correction

A serialized `static_checks[i].passed` value is now checked against the reconstructed report before `acceptance_passed` is evaluated. A re-signed archive with only that boolean changed is rejected. The focused package regression group is now 28 tests, and the full suite is **830 passed, 1 skipped**.
