# KinCheckAPI v0.1.4 更新报告

## 版本定位

v0.1.4 不增加新的机构类型，重点修复仿真 API 的可信度：坏拓扑必须在后端运行前被拒绝；几何残差和传动方程残差必须分开；结果状态必须能表示“算出了样本，但约束没有满足”；CadIR 物理量必须统一为 SI；多个初始关节状态必须联立求解；Component 和 Connector 的空间速度、加速度必须是真实数据，缺失时明确返回 `None`。

## 1. 拓扑校验成为强制门禁

`solve_motion()` 现在依次执行 `validate_assembly()`、`validate_topology()` 和 `validate_scenario()`。只要装配引用或拓扑存在 error，内置物理后端 就不会加载和编译；异常报告会一次保留全部结构化 issue，调用方可直接读取 code、object ID、证据和修改建议。

私有的 `compile_assembly()` 也无条件重复拓扑校验，避免绕开公共入口后把坏装配交给后端。无 Ground、断开岛、未知 Joint 端点、漏写 Closure、孤立 Closure 和重复父关系都有稳定的 `topology.*` issue code。

CadIR 的源关系没有单独的 Closure 类型。适配器现在会分析展开后的关系图，把确定的非树 Joint 提升为带来源 Joint ID 的 adapter Closure；因此 ex1-ex4 在严格门禁下仍能保留原有闭环语义。

多个互相独立、但都通过 Ground 固定到世界的刚体组是合法模型。此情况返回 `topology.multiple_roots` warning，不阻止编译；未接地的组件岛仍是 error。

## 2. 几何残差和方程残差彻底分开

`MotionResult.constraint_residuals` 只保存米制位置残差和弧度姿态残差。新增 `ConstraintEquationResidual` 和 `MotionResult.constraint_equation_residuals`，保存 gear、belt、Coupling 的真实线性方程残差：

```text
gear / belt  -> signed value，unit="m"
Coupling     -> signed value，unit="rad"
absolute_value = abs(value)
```

新增 `result.list_constraint_equation_residuals()` 和 `checks.check_constraint_equation_residuals()`。检查支持 Constraint/Coupling ID、方程类型、时间窗口、禁用 ID、米/弧度独立容差、最大绝对值、P95 和超差样本数。`.kincheck` 导出与读取会保留方程类型、单位、有符号值和绝对值。

这意味着“齿轮中心距没变”和“传动方程满足”现在是两份独立证据，不会再互相覆盖。

## 3. 求解状态能表示约束未满足

运动结果的成功返回状态现在有明确含义：

| 状态 | 含义 |
|---|---|
| `completed` | 后端完成采样，求解级约束都在容差内 |
| `completed_with_warnings` | 后端完成采样，没有求解错误，只有 warning |
| `partial` | 后端产生了样本，但至少一个几何或方程残差超出求解容差 |

普通 Constraint、gear、belt、Coupling 和 Closure 都参与状态汇总。超差会产生 `KINCHECK-CONSTRAINT-GEOMETRIC-RESIDUAL-EXCEEDED` 或 `KINCHECK-CONSTRAINT-EQUATION-RESIDUAL-EXCEEDED`，其中包含对象 ID、首次失败时间、实际最大值、容差和单位。

默认求解级几何和方程容差记录在 `MotionResult.metadata["solve_tolerances"]`，当前均为 `1e-6`，分别按 m 或 rad 解释。独立 Check 可以使用更严格的工程容差，所以 `completed` 不等于所有业务检查一定通过。

`try_solve_motion()` 对 `partial` 返回 `succeeded=True`，保留 `motion_result` 和 error issues，同时 `failure=None`。调用方必须检查 `attempt.status`，不能只看 `succeeded`。

## 4. CadIR 物理量完整归一化为 SI

适配器现在同时读取并验证 length、angle、mass 单位，并显式完成：

- `mm/cm -> m`；
- `degree/deg -> rad`；
- `g -> kg`；
- 已声明密度单位到 `kg/m^3`；
- placement、节圆半径、带轮半径、中心距、相位和 Joint limit 的统一转换。

只有 schema 已声明物理意义的字段会转换，任意 metadata 不会因为 key 名中含有 `mass` 或 `radius` 就被猜测缩放。转换后的 `AssemblyModel.metadata["units"]` 固定写为 `m/rad/kg/s`。

嵌套装配中的 `angle_limit` 和 `distance_limit` 会进入公共 `Joint.limit`。内置物理后端 编译器显式使用 radian，并把可映射到单个内部坐标的限位写为 `limited="true" range="lower upper"`。反向表达式会翻转区间；多个公共 Joint 共享坐标时取限位交集；空交集或多坐标硬限位会返回结构化 capability error，不再静默忽略。

## 5. 初始关节状态改为一次联立求解

初始位置和初始速度分别构造 `A q = b`，按 Joint ID 稳定排序后使用线性最小二乘一次求解。结果会在 `MotionResult.metadata["initial_state"]` 中记录：

- `source` 和 `status`；
- `rank`、行数、列数；
- residual norm 和最大绝对误差；
- 参与求解的 Joint ID；
- 每条目标的 target、actual 和 error。

状态区分 `unique`、`underconstrained`、`overconstrained_consistent`、`inconsistent` 和 `default_zero`。写入 内置物理后端 后会执行 `mj_forward()`，再读取内部状态逐条复核，不能只相信第一次线性求解结果。

不一致的初始条件会在第一个仿真步前转换为 `ScenarioValidationError`，稳定错误码为 `KINCHECK-SCENARIO-INITIAL-STATE-INCONSISTENT`；不会生成一份看起来完整但初始状态错误的运动结果。

## 6. Component/Connector 返回真实空间运动

后端样本新增 Component 和 Connector 的世界坐标线速度、角速度、线加速度、角加速度。数据来自 内置物理后端 site 的 object velocity/object acceleration 查询；运行时不能直接提供加速度时，使用真实采样时间对空间速度做有限差分，并在 `metadata["spatial_kinematics"]` 标记来源。

新增 `result.read_component_state()`；`read_connector_state()` 同步支持四组空间量。旋转轴外的 Connector 现在会得到真实切向速度和向心加速度，平移刚体也会正确区分线速度和角速度。

`Trajectory`、`ComponentState`、`ConnectorState` 的四组空间字段现在允许为 `None`。规则是：

- 后端确认静止：返回真实的零向量；
- 后端或旧结果包没有该数据：返回 `None`/JSON `null`；
- 不再把“未知”自动补成“静止”。

Component result scope 继续生效：只为用户请求的 Component/Connector 输出完整空间轨迹，用于内部残差计算的额外对象不会泄漏到结果中。

## 兼容性说明

- `MotionResult.constraint_residuals` 仍可用，但只表示几何残差；传动和耦合方程请读取 `constraint_equation_residuals`。
- 旧 `.kincheck` 缺少空间运动字段时会读成 `None`。外部代码应先判断再做向量运算。
- `partial` 是有结果的诊断状态，不抛异常；工程验收仍应调用 `checks.run_checks()`。
- 本版本没有改成网格齿面碰撞，也没有增加通用闭环位置求解、BREP 干涉或动力学。
