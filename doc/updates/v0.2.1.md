# KinCheckAPI v0.2.1 更新报告

## 版本定位

v0.2.1 把 KinCheckAPI 从“按时间播放一段运动”推进到“先判断一个运动状态是否可行，再分析它能怎样运动”。

本版本继续以 CadIR Artifact 和 `AssemblyModel` 作为运行时输入，不改变已有 `Scenario`、`MotionResult` 和 `.kincheck` 的基本使用方式。新增能力集中在单姿态运动学分析、工作空间分析和结果检查。

## 主要更新

### 1. Jacobian 和有效自由度

新增 `kincheckapi.kinematics.compute_jacobian()`，为指定组件或 Connector 计算几何 Jacobian。它描述每个关节发生微小运动时，目标点的线速度和角速度会怎样变化。

返回结果包含：

- 固定排序的 Joint ID 列表；
- 世界坐标系下的线速度和角速度矩阵；
- 矩阵秩、奇异值和条件数；
- 目标对象、单位和结构化诊断信息。

新增 `analyze_mobility()`，不再只把 Joint 数量相加，而是扣除 Closure、Coupling、gear、belt 等独立约束，报告名义自由度、约束秩和有效自由度。正反向 Connector 声明使用统一的关节正方向，避免几何分析和 内置物理后端 后端的符号不一致。

### 2. 单姿态求解和闭环收敛

新增 `solve_position()`，支持给定部分关节状态或目标 Pose，求一个满足树关系、闭环和传动约束的姿态。求解过程使用阻尼最小二乘迭代，并处理：

- revolute 和 prismatic Joint；
- Closure、Coupling、gear 和 belt；
- Joint limit；
- 目标组件或 Connector 的位置、方向；
- 不可达、初值不闭合、奇异和迭代不收敛。

失败时不会返回假成功结果。可预先发现的装配引用错误仍抛出结构化校验异常；求解过程中的不可行状态返回 `PositionResult(passed=False)`，其中保留最后状态、残差和失败原因。

闭环残差表示“本来应该重合或对齐的两个连接点，实际还剩多少误差”：位置残差单位为米，方向残差单位为弧度。残差接近零表示闭环方程满足，不代表已经完成碰撞或间隙检查。

### 3. 奇异点、可达性和工作空间

新增以下分析入口：

- `find_singularities()`：根据 Jacobian 的秩、最小奇异值和条件数识别正常、接近奇异和奇异状态；
- `check_reachability()`：判断目标 Pose 是否可达，并区分目标不存在、超出限位、闭环无法收敛、约束残差过大和奇异等原因；
- `compute_workspace()`：在调用方给定的有限 Joint 范围内进行确定性采样。

每个工作空间采样点都保存成功/失败、最终残差、Jacobian 秩、最小奇异值、条件数、奇异状态和失败原因。未知目标组件、Connector 或 Joint 会得到 `passed=False`，不会被汇总成错误的成功结果。采样种子会影响网格截断顺序，但相同输入仍得到可复现结果。

本版本提供可达点集合和统计摘要，不承诺 BREP 包络或碰撞过滤。

### 4. 轨迹、路径和限位检查

`checks.check_pose_target()` 和 `checks.check_trajectory()` 已经可以只读取 `MotionResult` 做业务检查，不修改求解结果。轨迹检查支持：

- 位置和方向目标；
- 轨迹路径长度；
- XYZ 坐标范围；
- 速度和加速度上限；
- 闭环/普通约束残差；
- 时间窗口过滤；
- 限位事件数量和越限事件。

新增 `kinematics.trace_connector_path()`，可以从已有结果统计 Connector 的路径长度、起点、终点、坐标极值和参考系。缺少请求的轨迹时返回明确的 `missing_trajectory` 问题。

采样阶段会生成 `MotionResult.limit_events`，记录首次触碰或越过上下限的 Joint、方向、时间、限值和实际值。限位检测不会修改驱动曲线或轨迹数据。

### 5. Joint lock

`Scenario.locked_joints` 现在会进入单姿态求解和 内置物理后端 时间域约束。锁定值与驱动或初始值冲突时，在求解前报告结构化冲突；锁定成功后，结果中仍保留对应关节的轨迹和状态。

### 6. 新增业务样例

新增两个 Artifact 示例，用于验证用户任务，而不是只测试 API 是否能调用：

| 示例 | 机构 | 验证任务 |
|---|---|---|
| ex5 | 曲柄滑块 | 输入旋转运动是否能带动滑块直线运动，闭环是否保持，末端路径和有效自由度是否正确 |
| ex6 | 平面双摆 | 两个转动关节是否形成预期的二维末端工作空间，末端 Jacobian 是否有正确秩 |

原有示例继续作为回归：

- ex1：三级行星减速器，运动仿真传动比 `64:1`；
- ex2：两级行星减速器，运动仿真传动比 `20:1`；
- ex3：四连杆，单姿态和时间域闭环；
- ex4：Theo Jansen 连杆，三条 Closure 的时间域闭环。

ex5/ex6 当前使用 Artifact 作为运行时输入；`.scadpkg` 转换不属于本版本。

## 结果和错误语义

本版本遵循“错误输入不能伪装成通过”的规则：

- 未知目标、Connector 或 Joint：返回结构化失败，不返回 `passed=True`；
- 不可达目标：返回 `passed=False`，并说明是限位、闭环、约束还是奇异导致；
- 迭代未收敛：保留最后状态和残差，状态为非成功状态；
- 已生成部分时间样本但有残差超差：`MotionResult.status` 为 `partial`；
- 没有实现的 BREP 碰撞/间隙、动力学等能力：抛出稳定的 capability error。

Jacobian 的角速度部分和闭环方向残差统一使用世界坐标系。结果中的位置量使用米，角度使用弧度，时间使用秒。

## 明确边界

v0.2.1 仍不包含：

- CAD BREP 级碰撞、最小间隙和运动包络；
- 质量、惯量、重力、力矩、摩擦、阻尼和完整动力学；
- 齿面接触、回差、效率和真实接触力；
- 所有复杂闭环机构的稳定时变位置求解保证；
- Cylindrical、spherical、planar、free 等当前后端未支持的 Joint 类型；
- `.scadpkg` 到 KinCheckAPI 的运行时转换。

错误模型会在校验或求解阶段明确失败，不会生成一段看似完整但实际不满足约束的动画。

## 测试和回归

本版本为每项新增公开能力补充了 5-10 个行为测试，覆盖正常输入、错误输入、边界值、确定性和结果序列化。专项测试覆盖：

- Jacobian 世界坐标和正反向 Connector 符号；
- 有效自由度、单姿态求解、闭环残差和限位；
- 奇异点、可达性和工作空间失败样本；
- Pose、轨迹、路径长度、坐标范围和限位事件检查；
- ex5/ex6 Artifact 机构业务流程；
- ex1-ex4 传动比和闭环运动回归。

最终回归结果：

```text
573 passed, 5 skipped
```

5 个跳过项只依赖当前环境中未安装的可选 `simplecadapi`；KinCheckAPI 核心、内置物理后端、ex1-ex6 和结果检查测试均通过。

运行完整测试：

```bash
uv run --extra test pytest -q
```
