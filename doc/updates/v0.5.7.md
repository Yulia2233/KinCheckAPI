# KinCheckAPI v0.5.7 更新说明

v0.5.7 增加跨轨迹样本的连续干涉检查，并修复详细四连杆示例中曾被漏检的连接区域干涉。此前 `check_interference()` 和 `check_minimum_clearance()` 只查询已经记录的离散时刻，两个样本之间的接触可能被漏掉；现在可以使用 `check_continuous_interference()` 对显式组件对建立可审计的连续时间证据。本次发布同时包含此前完成的 [v0.5.6 数值逆运动学](v0.5.6.md)，其能力范围和结果语义见对应说明。

## 连续干涉与 TOI

```python
from kincheckapi import ContinuousInterferenceOptions
from kincheckapi.clearance import check_continuous_interference

report = check_continuous_interference(
    assembly=assembly,
    motion_result=motion,
    component_pairs=(("link", "slider"),),
    asset_root=model_dir,
    options=ContinuousInterferenceOptions(
        time_tolerance_s=1e-5,
        minimum_clearance_m=5e-4,
        max_iterations=64,
        max_subdivisions=4096,
    ),
)
print(report.to_dict())
```

新增 `ContinuousInterferenceOptions`、`ContinuousContactEvent` 和 `ContinuousInterferenceReport`。实现对每一对组件缓存三角网格和 FCL 对象，在相邻位姿样本之间使用位置线性插值和最短弧 quaternion SLERP。包围球可先排除明显分离的区间；精查距离、相对线速度和角速度乘网格包围球半径共同给出保守下界。下界无法证明安全时，按时间顺序先检查前半区间、再检查后半区间；只有保守下界证明前缀安全才推进 TOI 下界，不能凭一个未碰撞的中点跳过前面的时间。事件区间保留最早尚未排除的时刻到已观测接触时刻，`earliest_contact_time_s` 是首次接触时间的上界（对应一个已观测到接触的时刻），`toi_tolerance_met` 记录是否达到要求的时间精度。

`ContinuousInterferenceOptions.interpolation` 可选 `slerp_pose` 或 `linear_pose`。后者要求被检查组件的姿态保持不变；姿态发生变化时返回结构化 `validation_failed`。`time_tolerance_s`、`distance_tolerance_m`、`max_iterations`、`max_subdivisions`、`max_queries` 和 `minimum_clearance_m` 都会保留在报告中。

## 结果、诊断与五项复审修复

- `passed`：所有请求区间都有完整覆盖，并取得大于安全间隙的保守距离下界。
- `failed`：检测到初始重叠、接触或低于安全间隙的区间；事件包括对象 ID、时间区间、接触时间上界、最近点、法向（若 FCL 提供）、相对速度和 certainty。
- `indeterminate`：尚未观测到确认碰撞，但时间轴、数值预算或几何证据不足，不能把结果解释为安全。已确认碰撞即使随后预算耗尽仍保持 `failed`，同时保留覆盖未完成、预算原因和原始 options。
- `capability_failed`：FCL、trimesh 或 rtree 不可用；返回 `KINCHECK-CLEARANCE-CONTINUOUS-BACKEND-UNSUPPORTED`。
- `validation_failed`：组件对、参数、时间窗、网格或插值声明不合法。
- `partial`：输入运动结果未完整完成，保留原因，不能作为连续安全证明。

连续检查只接受 `completed` 或 `completed_with_warnings` 的 `MotionResult`。`partial` 结果仍可用于离散诊断，但不能产生连续通过。结果可以通过 `record_verification_reports()` 写入 `MotionResult.metadata`，随 `.kincheck` 运动包保存，读取后事件区间、certainty、options 和状态保持不变。

接触速度使用世界坐标中的 `v_B(point_B) - v_A(point_A)`，每个点速度都包含 `v_origin + ω × r`。闭合速度和接触角从该速度与报告法向计算；没有可用法向时相应字段为 `null`。接触前状态取最后一个实际查询到的分离样本，不能解释为之前所有时间都无碰撞。

`minimum_clearance_m` 仅记录实际网格查询的最小距离，不表示全域最小值；若全程用包围球排除而没有网格查询则为 `null`。`clearance_lower_bound_m` 只有在所有区间均证明安全时才有值；发生碰撞或覆盖不完整时为 `null`。局部安全区间及其下界保留在 `metadata.certified_intervals`。

`checks.check_continuous_interference()` 和 `run_checks()` 拒绝未识别参数。例如直接传 `minimum_clearance_m=0.2` 返回 `validation_failed` 并提示放入 `options`，不再静默使用默认阈值。

五项复审问题均有复现回归：

| 原问题 | 修复后的行为与证据 |
| --- | --- |
| TOI 二分跳过更早接触 | 按时间顺序证明安全前缀；双障碍用例的首个接触区间为 `[0.2666626, 0.2666702] s`，包含真实首次接触时间。 |
| 包装函数丢弃安全阈值 | 错放阈值返回 `validation_failed`，提示放入 `options`。 |
| 旋转接触速度为零 | 在报告接触点计算 `v_origin + ω × r`；纯旋转用例约为 `2.51818 m/s`，与独立计算一致。 |
| 查询预算耗尽丢失碰撞 | 保留确认事件、对象、时间及规范化 options；已确认碰撞保持 `failed`，同时记录未完成覆盖。 |
| 局部安全下界被误作全域下界 | 碰撞或覆盖未完成时 `clearance_lower_bound_m=null`，实测距离和局部区间证据独立保存。 |

## 完整四连杆示例与几何查询优化

[guided_four_bar_actuator](../../examples/guided_four_bar_actuator/README.md) 提供 CADIR/SimpleCADAPI 建模、MJCF 导出、独立验证和 `.kincheck` 回放。它包含底座、三根杆、四个实体销轴及护罩，共 9 个实体。原来只检查两组非连接组件对，扩大范围后发现底座/曲柄、底座/摇杆、连杆/曲柄、连杆/摇杆四组初始干涉，已修改建模源码并重导出几何：曲柄及摇杆中心位于 Z=5 mm，连杆中心位于 Z=10 mm，杆厚 4 mm、杆面间隔 1 mm；轴孔半径 2.30 mm、销轴半径 2.00 mm，重新匹配销轴长度、头部与落座肩，护罩支脚落在底座顶面 Z=-4 mm。原四连杆中心距、驱动和 0–2 s 工况保持不变。

验证覆盖全部 36 个实体配对，没有因销轴连接而排除整个组件对。其中 28 组相对运动实体对由 6 组完整刚体复合网格进行离散及连续检查；其余 8 组固定实体对通过独立初态网格检查和相对变换不变性覆盖全程，允许设计落座面接触但不允许穿透。另对全部 36 对执行实体初态补查。201 个采样时刻的离散检查及 200 个时间区间的连续检查通过，活动组件要求间隙 0.1 mm，报告全域保守下界约 **0.101667 mm**、实际查询最小距离约 **0.200000 mm**。

检测器负例在 t=1 s 将真实连杆下移 5 mm，故意破坏正常装配关系，离散及连续检查均检出碰撞；它单独标注为负例，不属于交付模型的正常运动。包内保存验收报告、36 对范围、连续选项及区间证据、负例结果，并已读回核对。详见 [碰撞复核说明](../../examples/guided_four_bar_actuator/output/collision_review.md)、[完整 JSON 证据](../../examples/guided_four_bar_actuator/output/collision_verification.json) 和 [可视化包](../../examples/guided_four_bar_actuator/output/guided_four_bar_actuator.kincheck)。

实体包含检测改为每批查询 32 个顶点：发现任意顶点在外部，便可提前否定该连通实体被完全包含，随后仍继续检查其他连通实体；确认包含仍要求全部顶点通过。该短路保持原判定条件，不减少碰撞配对、不简化网格，也不放宽容差。当前示例连续检查记录 3,412 次精细查询和 125 次额外细分；尚未实现跨离散/连续检查共享查询、复用包含检测空间索引或组件对并行，不能把不同版本运行时间视作缓存加速对照。

## 保持的边界

现有离散干涉、最小间隙和运动包络 API 保持不变。连续检查要求明确、非空的组件对，每个组件至少两个位姿样本且时间窗均被覆盖，有效闭合的 STL 网格，以及 python-fcl、trimesh、rtree 后端。能力取决于刚体网格和轨迹，不限于四连杆或特定关节类型；只有关节数值而没有组件位姿轨迹时不能检查。

v0.5.7 的连续证明只针对已记录组件的分段刚体位姿模型，不等于证明样本之间真实机构运动与插值严格一致，也不是精确 BREP/NURBS 扫掠证明。它不覆盖变形体、摩擦、冲击、接触力、动力学积分或未声明组件对。接触法向和角度依赖可用几何证据；无法证明的区间必须保留为 `indeterminate`。四连杆通过结论仅针对交付几何与原定 0–2 s 工况，不外推到整圈运动或其他载荷。
