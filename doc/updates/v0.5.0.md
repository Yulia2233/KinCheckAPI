# v0.5.0 更新记录

## 版本目标

v0.5.0 把 KinCheckAPI 的受控失败收敛为一个无参数 Agent 输出协议：

```python
str(error) == error.format_for_agent()
str(result) == result.format_for_agent()
```

错误正文固定包含错误码、操作、发生事实、可用定位信息、修复动作和技术类型；
结果正文以 `passed`、`failed`、`partial`、`capability_failed` 或
`validation_failed` 开头。格式化器不接受 `style`，也没有第二套文本分支。

## 公共 API

- `KinCheckError` 及其公开子类可直接打印，并保留 `operation`、`status`、report 和
  JSON-safe 技术细节。
- `ValidationResult`、`DiagnosticReport`、检查、clearance、运动、求解 Attempt 和
  分析报告统一实现 `format_for_agent()`、`__str__()` 与 `raise_if_failed()`。
- `raise_if_failed()` 抛出引用原结果的 `VerificationError`；捕获后的正文与直接
  打印原结果相同。
- `format_result_for_agent(result, operation=None)` 是无状态兼容函数；
  `format_report_for_agent()` 仅为旧名称委托，二者都不接受样式参数。
- 结果读取函数把公开边界的 `KeyError`、`TypeError` 和 `ValueError` 转换为稳定
  `KinCheckError`，并记录请求 ID、可用 ID 和底层异常类型 evidence。

## 结构化记录

`to_dict()` 继续作为机器接口，保留 issues、objects、sources、evidence、actions、
operation 和 status，不写入 traceback。`fail/_common.py` 的 envelope 在结构化
`result` 或 `error` 之外增加顶层 `agent_output`，且正文完全由对象自身生成。

全部 `fail/01`-`15` 和编号矩阵已迁移到维护中的闭环 MJCF fixture；验证示例和
实例脚本使用 `raise_if_failed()`，不再抛出手工 `RuntimeError(check.to_dict())`。

## 兼容边界

本版本不改变运动求解、验证阈值、几何算法或 `.kincheck` 包 schema。下游仍可读取
`to_dict()`；迁移期不得恢复样式枚举或第二种文本格式。
