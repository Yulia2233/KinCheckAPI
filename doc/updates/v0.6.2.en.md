# KinCheckAPI v0.6.2 update

v0.6.2 adds finite-actuator forward dynamics. `ActuatorSpec` binds an actuator ID to a joint and declares maximum effort, maximum speed, and efficiency. `ActuatorProfile` is a time-ordered effort command. `ForwardDynamicsRequest` fixes the initial state, gravity, external loads, duration, and sampling period. `solve_forward_dynamics()` integrates MuJoCo with explicit CADIR inertials and records joint position, velocity, acceleration, applied effort, input energy, peak power, and peak effort.

`check_dynamic_tracking()` checks final scalar positions against explicit targets. Effort saturation is enforced by the backend actuator bound; `max_speed` is an acceptance constraint. The E01 dynamic verifier now exercises both the inverse-dynamics rating and a 0.2 s finite-motor case.

The capability remains limited to scalar revolute/prismatic trees without closures. Closed-loop mechanisms continue to use the kinematic solver and continuous geometry checks; a finite-drive result is not a contact, friction, collision, or structural-safety proof. Samples must be strictly time ordered, and non-finite states, backend failures, and speed-limit violations cannot be reported as passes.
