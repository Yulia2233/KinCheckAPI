# KinCheckAPI v0.5.4

This pre-update connects scenario authoring, deterministic solver controls, and acceptance evidence. It adds non-overlapping `MotionSegment` drivers, explicit home-state initialization, typed `KinematicSolveOptions`, backend capability reporting, typed internal integration samples, `DriverTarget`/`DriverTrajectory` records, strict joint/component/connector result filtering, and `check_driver_tracking()` metrics. `completed` still means only that integration finished; driver tracking is an independent acceptance check.

The slider-crank acceptance program is `examples/slider_crank/verification/verify.py`. The CADIR modeling source is `examples/slider_crank/model/source/slider_crank.cadir.py`; it has generated `slider_crank.scadpkg`, MJCF, mapping, and four mesh assets. The environment currently has SimpleCADAPI 2.1.3b1, below the addon's required `>=2.1.3b3,<2.1.4`; the source includes a narrow b1 placement-tick normalization branch that should be removed and re-exported with b3.

Direct execution of the verifier also emits JSON; failures contain structured error codes, status, and evidence and use a non-zero exit code.

Backward compatibility is preserved for existing Scenario fields and setters. `solve_motion(options=None)` keeps its previous behavior; new controls use `KinematicSolveOptions`.
