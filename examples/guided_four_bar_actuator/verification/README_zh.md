# 导向四连杆执行机构验证

验证程序独立于建模代码，只消费同一次 CADIR 导出的 MJCF、mapping 和实体网格。运行：

```bash
python verification/verify.py model --report output/collision_verification.json
python verification/export_motion_package.py
```

碰撞覆盖范围包括全部 9 个实体零件（底座、护罩、3 根杆件、4 根销轴），共 36 组实体配对，**没有排除相邻关节组件对**。

- 28 组实体相对运动配对由全部 6 组刚体复合网格配对覆盖：对完整 0–2 s、201 个采样执行离散干涉、最小间隙和连续检查，要求至少 0.1 mm 间隙。复合网格包含组内的每个销轴和其他固定件。
- 8 组同刚体内实体配对单独执行初态穿透和间隙检查；其相对位姿严格不变，因此该结论覆盖整个运动。底座/护罩以及销轴支承肩/宿主面的设计落座允许表面贴合，所有实体均不得穿透。
- 全部 36 组实体配对还执行独立初态干涉检查，防止刚体合并隐藏内部错误。

`collision_scope.py` 用已校验的 MJCF geom 变换和组轨迹恢复实体运动，使用建模阶段导出的 `collision_meshes/*.stl`，不构造简化碰撞体。文件缺失或九实体范围不完整直接失败。

`collision_checks.py` 还包含检测器负例：在 t=1 s 将真实连杆网格下移 5 mm，要求离散与连续检测均返回 `failed`，并指向曲柄/连杆及对应时间。这个故意破坏关节关系的位姿只用于测试检测器，不属于正常模型；“负例测试通过”表示成功发现碰撞。

其余验收继续检查拓扑、闭环残差、驱动跟踪、关节限位、摇杆速度及装配连通性。完整证据写入 `output/collision_verification.json`；导出脚本保存同一次求解的全部验收报告、检查范围及负例结果到 `.kincheck`。
