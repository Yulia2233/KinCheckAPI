# 运动学正确性

KinCheckAPI 里的“正确”不是“求解器没有抛异常”，而是模型在指定工况下满足可检查的运动学事实。

## 必查层次

1. **模型层**：组件、connector、joint、ground、closure、coupling 的引用存在，ID 唯一，单位和姿态合理。
2. **拓扑层**：运动树连通，ground 明确，闭环数量符合设计，自由度与驱动数量没有明显矛盾。
3. **姿态层**：给定初始关节位置能得到合法姿态，闭环位置和方向残差在阈值内。
4. **运动层**：给定驱动能在完整时间窗内完成，采样足够，关节不超限，传动关系符合预期。
5. **任务层**：目标 component/connector 的位姿、轨迹、可达性或工作空间满足用户要求。
6. **安全层**：如用户要求，使用明确组件对检查干涉和最小间隙。

任何一层失败都应说明失败层和证据，不能用下一层的结果掩盖上一层的问题。

## 常见误判

- `status == "partial"` 不是“基本通过”；它只是失败前的有效轨迹。
- `checked_sample_count == 0` 不是“没有干涉”；它是没有执行有效检查。
- 只有一个自由度报告不是机构运动正确的证明；还需验证目标运动和约束残差。
- 关节 `range` 是模型中写入的限位；缺失范围时，限位检查可能报告未建模，而不是自动通过。
- 运动学验证和几何干涉验证是两个维度，不能互相替代。
