# v0.8.0 预备更新：KinCheck Native GUI 与验证脚本导出

> 状态：实现基线文档，2026-09-22。目标是为 KinCheckAPI 增加一个独立的本地桌面 GUI。GUI 不复用 `viewer/`，不导入 Viewer 代码，也不包含 FEACheckAPI 能力。

## 1. 目标

用户可以在一个本地桌面窗口中选择模型、配置工况、运行当前 KinCheckAPI 支持的运动学和刚体动力学分析，并直接查看结构化结果。每个 GUI 工况都必须能导出成独立 Python 验证脚本，使 GUI 操作可以在无 GUI 环境中重复执行。

本版覆盖：

- 运动学轨迹、位姿、传动、限位、间隙、干涉和连续干涉检查；
- v0.6 标量逆/正动力学及给定外力接触容量检查；
- v0.7 多自由度刚体状态、KKT 约束、反力、source map、耦合 penalty 接触、摩擦、冲量、控制器、急停、制动、随机激励、WrenchProfile、DutyCycle 和工况矩阵；
- 刚体物性/静力结果的读取和展示；
- `.kincheck` 结果包导出和 `dynamics.json` 历史回放。

结构网格、应力、变形、结构振动、模态和疲劳不出现在 GUI 分析列表中，继续由独立 FEACheckAPI 负责。

## 2. 产品形态

采用 Python 原生 Tk GUI 作为 v0.8.0 的基础运行时，避免增加必须的桌面框架依赖；3D 场景和曲线采用可替换的 GUI 组件接口。没有 Tk 运行时或在无显示环境中启动时，CLI 返回结构化 capability failure。

入口：

```bash
kincheck gui
kincheck gui --scenario path/to/scenario.json
```

GUI 不调用 `viewer/kincheck_viewer.py`、`viewer/static/` 或 `viewer.json`。它有独立的窗口、状态模型、结果模型和绘制组件。

## 3. 分层设计

```text
Tk GUI
  ├─ ModelPanel / ScenarioPanel / ResultPanel
  ├─ RunController（后台 worker、进度、取消）
  └─ GuiResultPresenter
       │
       └─ GuiSimulationService
            ├─ scenario_document.py
            ├─ capability_probe.py
            ├─ simulation_service.py
            └─ verification_export.py
                 │
                 └─ KinCheckAPI public APIs
```

GUI 层只负责编排、输入校验、结果呈现和脚本生成；求解仍由现有公开 API 完成。后台任务不得执行任意用户代码，验证脚本导出只从已校验的 typed scenario 生成。

## 4. 工况文档

GUI 使用独立的 `kincheck.gui-scenario/1.0` JSON 文档。运动学输入使用 `model.assembly_json`；标量动力学和刚体静力使用 `model.dynamics_model_json` 或 `scenario.dynamics_model`，其中包含装配和显式刚体物性：

```json
{
  "schema_version": "kincheck.gui-scenario/1.0",
  "document_id": "startup-demo",
  "model": {"path": "model", "sha256": null},
  "analysis": "multibody",
  "scenario": {},
  "cases": [],
  "checks": [],
  "run_options": {"strict": true}
}
```

`analysis` 只允许已支持的分析类型。多工况使用 `cases`，每个 case 必须有稳定 `case_id`。文档保存的是请求，不是假定结果；结果另存为 `.kincheck` 或 JSON。

## 5. 窗口功能

### 模型和能力

- 选择模型目录或输入文件；显示路径、哈希、装配 ID 和单位；
- 调用能力探测，禁用不支持的表单选项；
- 展示明确的 `validation_failed`、`capability_failed`、`indeterminate` 原因。

### 工况

- 选择分析类型；
- 编辑标量状态、广义状态、质量矩阵、约束、接触、控制器和载荷；
- 添加、复制、删除和排序工况；
- 保存/加载工况 JSON；
- 运行前执行严格 schema、有限值、单位、引用和覆盖率校验。

### 结果

- 3D/二维装配示意和时间轴；
- 轨迹、速度、加速度、力、反力、接触事件、冲量、能量和 RMS 的曲线/表格；
- 工况矩阵覆盖状态；
- 原始诊断、source map、模型/工况哈希和结果状态；
- 导出 `.kincheck`、原始 JSON 和验证脚本。

## 6. 后台任务

仿真在独立 worker 中运行，主窗口不会因求解阻塞。任务状态为：

`queued → running → completed | failed | indeterminate | capability_failed | cancelled`。

worker 只接收 JSON 工况并调用公开 KinCheckAPI 类型；每次运行返回 `run_id`、输入哈希、已完成 case、有效结果前缀和诊断。取消操作只能中止当前任务，不会把部分结果标记成通过。

## 7. 验证脚本导出

GUI 对每个工况生成：

```text
verification/
├─ verify.py
├─ scenario.json
├─ model-reference.json
└─ README.md
```

`verify.py` 必须：

1. 读取并校验 `scenario.json`；
2. 校验模型路径和模型哈希；
3. 重建对应 KinCheckAPI typed request；
4. 调用同一个公开求解入口；
5. 输出结构化 JSON；
6. 在失败、能力不足或 `indeterminate` 时返回非零退出码。

脚本不得导入 GUI 或 Viewer，支持 `--model`、`--output` 和 `--strict` 参数。导出的脚本使用固定 JSON 数据，不拼接未经转义的 Python 表达式。

## 8. 验收标准

- 无 GUI 环境可测试 `scenario_document`、能力探测、仿真服务和脚本导出；
- 同一工况通过 GUI 和导出脚本得到相同状态、case ID、模型哈希和关键数值；
- 旧纯运动包和旧静力包仍可读取；
- v0.7 `dynamics.json` 可从 GUI 导出并重新读回；
- 非法输入、未知分析类型、空工况、模型哈希不匹配和不支持能力均结构化失败；
- GUI 测试不导入 `viewer`，也不暴露 FEA 分析选项；
- 全量回归测试、GUI 服务测试和脚本子进程测试通过。

## 9. 版本边界

v0.8.0 交付一个可运行的本地工况工作台、服务层、结果面板和验证脚本导出。高级 CAD 3D 渲染、瞬时 restitution、真实几何碰撞搜索和 FEACheckAPI 仍不在本版范围内。
